# 용어

> 이 저장소의 **정본 이름**. 화면 · 문서 · 코드가 같은 것을 같은 이름으로 부르기 위해 둔다.
> 새 문구를 쓰기 전에 여기를 먼저 본다. 여기에 없는 개념이면 **이 파일에 먼저 적고** 화면에 쓴다.

## 왜 이 파일이 필요한가

한 화면에서 **네 층의 말**이 섞인다.

| 층 | 무엇 | 이 저장소에서 |
|---|---|---|
| **핵심** | 광고 귀속 — 누가 어디서 왔고, 그 성과를 어느 광고에 붙일 것인가 | `src/Attribution` `src/Collect` |
| 전달 | 그 사실을 매체에 되돌려 보내기 | `src/Dispatch` `src/Channel` |
| 검증 | 되돌린 것이 실제로 도착했는지 | `src/Verify` `src/Metrics` |
| **무대** | 측정 대상인 웹툰 서비스 — **도메인이 아니다** | `works` `episodes` `locales` |

여기에 **업계 말**(first-touch, CAPI), **코드 이름**(`touchpoints.position`), **화면 한국어**(접점 · 유입)가 겹친다.
같은 것을 두 이름으로 부르면 화면이 스스로를 설명하지 못한다. 그래서 정본을 정한다.

**이 시스템의 핵심은 귀속이다.** 전달과 검증은 *귀속을 믿을 수 있게 만드는 수단*이다 — 용어의 무게도 그 순서를 따른다.

## 읽는 법

각 항목은 **정본 이름 · 코드 이름 · 업계 이름 · 정의 · 쓰지 않는 말** 로 적는다.
비율에는 **분자와 분모**를 적는다 — 분모 없는 비율은 이 저장소에서 지표가 아니다.

---

## 1. 핵심 — 귀속

### 방문 (visit)

| | |
|---|---|
| 코드 | `visits` · 쿠키 `ab_vid` · 파라미터 `vid` |
| 업계 | visit / session |
| 정의 | 한 사람의 한 번의 브라우징. 쿠키 하나가 방문 하나를 가리킨다 |

### 브리지 (bridge)

| | |
|---|---|
| 코드 | `GET /go` → `Bridge::go()` · `302` |
| 업계 | click tracker / redirect endpoint |
| 정의 | **광고 링크가 먼저 들르는 서버.** 유입을 적고 `302` 로 랜딩에 넘긴다 |

광고에서 랜딩으로 바로 들여보내면 **기록할 기회가 없다.** 한 번 거쳐 가는 것이 이 엔드포인트의 존재 이유다.
`301`(영구)로 하면 브라우저가 기억해 두 번째 클릭부터 서버에 오지 않는다 → [`failure-scenarios.md`](failure-scenarios.md)

### 접점 (touchpoint) ★

| | |
|---|---|
| 코드 | `touchpoints` (`position` = `first` \| `last`) |
| 업계 | touchpoint |
| 정의 | **방문에 붙는 유입 기록 한 건.** 어디서 왔는지를 말한다 |
| 쓰지 않는 말 | ~~유입~~ 단독. "최초 유입 / 마지막 유입" 은 **최초 접점 / 마지막 접점** 으로 쓴다 |

방문 하나에 접점은 최대 둘이다 — `UNIQUE (visit_id, position)` 이 그 규칙을 스키마로 못 박는다.

### 최초 접점 · 마지막 접점 (first touch · last touch)

| | |
|---|---|
| 코드 | `position = 'first'` / `'last'` |
| 업계 | first touch / last touch |
| 정의 | 그 방문에 **처음** 붙은 접점 / **마지막으로** 붙은 접점 |

갱신 규칙 넷은 `src/Attribution/TouchpointResolver.php` 가 가진다. 화면(`/tour`)은 그 번호를 그대로 쓴다.

### 유입 소스 (source)

| | |
|---|---|
| 코드 | `utm_source` `utm_medium` `utm_campaign` `pid` `gclid` `fbclid` |
| 업계 | UTM parameter / click ID |
| 정의 | 접점에 실린 **매체 식별값**. 이 값이 있으면 광고 유입이다 |
| 쓰지 않는 말 | ~~유입 파라미터~~ 는 **URL 에 붙은 파라미터 자체**를 가리킬 때만 쓴다(브리지 입력 이야기) |

### 광고 유입 · 직접 유입

| | |
|---|---|
| 코드 | `pid`·`utm_source`·`gclid`·`fbclid` 중 하나라도 있음 / 전부 없음 |
| 업계 | paid(referred) / direct |
| 정의 | 유입 소스가 **있는** 접점 / **없는** 접점 |

**직접 유입은 마지막 접점을 덮지 않는다**(규칙 3). 덮으면 그 방문의 전환이 어느 매체에도 귀속되지 않는다.

### 귀속 (attribution) ★

| | |
|---|---|
| 코드 | `conversions.visit_id` → `touchpoints` · `Payment_model::attribution()` |
| 업계 | attribution |
| 정의 | **전환을 어느 접점(= 어느 매체)에 붙일 것인가를 정하는 일** |

두 층이다.
1. **어느 방문에 붙는가** — 결제 시점 방문이 있으면 그쪽, 없으면 가입 접점(`users.signup_visit_id`)
2. **그 방문의 어느 접점에 붙는가** — 최초 접점 기준인가 마지막 접점 기준인가

### 귀속 기준 (attribution basis)

| | |
|---|---|
| 정본 | **first-touch 기준 · last-touch 기준** |
| 정의 | 전환을 최초 접점에 붙일지, 마지막 접점에 붙일지 |

**한 기준을 고르지 않는다.** 지표 화면은 둘을 나란히 내고 차이를 표시한다 — 정산에서 다투는 자리가 거기다.

### 광고 귀속 전환

| | |
|---|---|
| 정의 | **광고 유입 접점이 붙은 전환** |
| 분모 | 전환 전체 |

"광고가 만든 결제" 라고 부르지 않는다 — 세는 것은 결제만이 아니라 전환 전체(결제 · 환불 · 가입)다.

---

## 2. 전환

### 전환 (conversion)

| | |
|---|---|
| 코드 | `conversions` (`type` = `purchase` \| `refund` \| `signup`) |
| 업계 | conversion / event |
| 정의 | 매체에 되돌려 보낼 값어치 있는 사건 |

**금액의 부호는 유형이 가진다.** `refund` 의 `value_minor` 도 **양수**(원 결제 금액 그대로)라, 유형을 보지 않고 더하면 환불이 매출이 된다.

### 중복 차단 (deduplication)

| | |
|---|---|
| 코드 | `conversions.dedup_key` UNIQUE · GA4 `transaction_id` · Meta `event_id` |
| 업계 | deduplication |
| 정의 | 같은 사건이 두 번 와도 한 번만 세는 것 |

막힌 건은 **행을 남기지 않는다** — 그래서 화면이 "몇 건을 막았는지" 셀 수 없다.

## 3. 전달

### 아웃박스 (outbox) · 적재 (enqueue)

| | |
|---|---|
| 코드 | `dispatch_outbox` · `Conversion_model::createWithOutbox()` |
| 업계 | transactional outbox |
| 정의 | **적재** = 전환과 *보낼 것*을 **같은 트랜잭션**에 적는 일 |

적재율이 100% 가 아니면 "전환은 됐는데 보낼 것이 안 만들어진" 자리가 있다는 뜻이다.

### 전송 (dispatch) · 채널 (channel)

| | |
|---|---|
| 코드 | `src/Dispatch` · `src/Channel` (`ga4` `meta` `noop`) |
| 업계 | server-side conversion API (GA4 MP · Meta CAPI) |
| 정의 | 적재된 것을 매체 API 로 보내는 일 / 보내는 곳 |

### 가짜 채널 (noop channel)

아무 데도 보내지 않는 채널. **분모에 섞으면 안 된다** — 9,303건 중 9,300건이 `noop` 이었고 합친 값은 100% 였다.

### 도달률 (delivery rate) ★ 우리가 지은 말

| | |
|---|---|
| 분자 / 분모 | 매체가 `2xx` 를 돌려준 전송 / 전송 시도 |
| 코드 | `dispatch_log.http_status` |
| 업계 | 표준어 없음 |

무응답(타임아웃 · 커넥션 실패)은 **실패로 센다.** 빼면 분모가 조용히 줄어 값이 오른다.

## 4. 검증

### 되읽기 (readback)

| | |
|---|---|
| 코드 | `src/Verify` · `php public/index.php cli/verify ga4` |
| 업계 | 표준어 없음 (GA4 Data API 조회) |
| 정의 | **매체 보고서를 우리가 다시 읽어** 보낸 것과 맞대는 일 |

### 반영률 (reflection rate) ★ 우리가 지은 말

| | |
|---|---|
| 분자 / 분모 | 매체 보고서에 있는 전환 / 보낸 전환 |
| 업계 | 표준어 없음 |

**측정 시각이 없으면 뜻이 없는 숫자다.** 같은 전송이 `+0h` 에 1.2%, `+40h` 에 100% 였다.
**도달률 ≠ 반영률.** `2xx` 는 "받았다" 지 "집계했다" 가 아니다.

---

## 5. 숫자를 말하는 규칙

| 말 | 뜻 |
|---|---|
| **분모** | 비율은 `몇 / 몇 (몇 %)` 로만 적는다. "95%" 는 20건 중 19건일 수도, 500건 중 475건일 수도 있다 |
| **표본** | 100건 미만이면 `표본 N` 을 붙인다. 아직 판정이 아니다 |
| **측정 시각** | 되읽어야 아는 값(반영률)에는 언제 쟀는지를 붙인다 |

---

## 6. 무대 — 측정 대상 (도메인이 아니다)

`works` · `episodes` · `work_publish_days` · `locales` 는 **측정할 대상**으로 만든 웹툰 서비스 모형이다.
연재 요일 · 기다리면 무료 · 언어와 문자 축 · 순위 기준은 [`data-model.md`](data-model.md) 6장과 [`research-method.md`](research-method.md) 3-1 이 가진다.
이 층의 말은 **귀속 이야기와 섞지 않는다.**

---

## 7. 쓰지 않는 말

| 쓰지 않는 말 | 대신 | 왜 |
|---|---|---|
| 최초 유입 · 마지막 유입 | **최초 접점 · 마지막 접점** | 같은 것을 "접점" 과 "유입" 두 이름으로 불렀다 |
| 유입(단독으로 접점을 가리킬 때) | **접점** | 〃 |
| 유입 파라미터(값을 가리킬 때) | **유입 소스** | 파라미터는 URL 에 붙은 것, 소스는 접점에 실린 값 |
| 광고가 만든 결제 | **광고 귀속 전환** | 세는 것은 결제만이 아니라 전환 전체다 |
| 전송 성공률 | **도달률**(2xx) 또는 **반영률**(보고서) | 하나로 부르면 두 사건이 한 숫자가 된다 |

## 이 파일을 고칠 때

용어를 바꾸면 **화면 · 문서 · 코드 주석 세 곳에 `grep`** 을 돌린다. 이름만이 아니라 **개념**으로도 찾는다.
바꾼 이유를 이 파일에 남기면, 다음 사람이 같은 자리에서 다시 고민하지 않는다.
