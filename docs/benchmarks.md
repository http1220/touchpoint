## 1. 인덱스 — 아웃박스 폴링 쿼리

```sql
SELECT * FROM dispatch_outbox
WHERE status = 'pending' AND next_retry_at <= NOW(3)
ORDER BY id LIMIT 100
FOR UPDATE SKIP LOCKED;
```

### 1-1. `EXPLAIN` before / after

| 상태 | `type` | `key` | `rows` | `Extra` | 실행시간 |
|---|---|---|---|---|---|
| 인덱스 없음 | | | | | ☐ |
| `(status)` 단일 | | | | | ☐ |
| **`(status, next_retry_at, id)`** | | | | | ☐ |

**절차**
1. `dispatch_outbox`에 100만 행 주입 (pending 5%, sent 95%)
2. 각 상태에서 `EXPLAIN` 원문 캡처
3. 쿼리 10회 실행 후 p50·p95

**기대**: 풀스캔(`type: ALL`) → 범위 스캔(`type: range`, `Using index condition`)

### 1-2. 컬럼 순서를 바꾸면

| 인덱스 | 예상 | 결과 |
|---|---|---|
| `(status, next_retry_at, id)` | range + 정렬 활용 | ☐ |
| `(next_retry_at, status, id)` | 범위가 앞이라 `status` 활용 저하 | ☐ |
| `(status, id, next_retry_at)` | 정렬은 되나 범위 필터가 인덱스 밖 | ☐ |

> **규칙 검증**: 등호 → 범위 → 정렬. 범위 조건 뒤의 컬럼은 정렬에 쓸 수 없다.

### 1-3. 코인 잔액 집계

```sql
SELECT SUM(remaining) FROM coin_lots
WHERE user_id = ? AND remaining > 0 AND expires_at > NOW(3);
```

| 인덱스 | `rows` | 실행시간 | 결과 |
|---|---|---|---|
| 없음 | | | ☐ |
| `(user_id)` | | | ☐ |
| `(user_id, remaining, expires_at, kind)` | | | ☐ |

## 3. 구간별 소요 시간

`dispatch_log`의 `parse_ms` / `db_ms` / `send_ms` / `total_ms`를 분리 측정한다.

| 구간 | p50 | p95 | p99 | 비중 | 결과 |
|---|---|---|---|---|---|
| `parse_ms` (페이로드 생성) | | | | | ☐ |
| `db_ms` (상태 갱신) | | | | | ☐ |
| **`send_ms`** (외부 HTTP) | | | | | ☐ |
| `total_ms` | | | | | ☐ |

**가설**: `send_ms`가 전체의 90% 이상. 병목은 외부 매체 응답이지 우리 코드가 아니다.

> 이 방식은 **RTSP 스냅샷 응답을 7단계로 쪼개 병목을 특정했던 접근을 그대로 이식한 것**이다. 새로 배우는 게 아니라 하던 걸 옮기는 것이라 빠르다.

## 4. 재시도 백오프 — 값을 실험으로 정한다

**초기 후보**

| attempt | 대기 | 누적 |
|---|---|---|
| 1 | 즉시 | 0s |
| 2 | 30s | 30s |
| 3 | 2m | 2.5m |
| 4 | 10m | 12.5m |
| 5 | 1h | ~1.2h |
| 6+ | `dead` | |

**검증할 것**

| 질문 | 측정 방법 | 결과 |
|---|---|---|
| 몇 번째 시도에서 대부분 성공하는가 | `dispatch_log`의 `attempt` 분포 | ☐ |
| 30초가 적절한가, 너무 짧은가 | 매체 장애 주입 후 회복 시각 관측 | ☐ |
| `dead` 컷을 6회로 두면 유실률은 | 최종 실패 건수 ÷ 전체 | ☐ |
| 지터(jitter)가 필요한가 | 동시 재시도 몰림 관측 | ☐ |

> **"왜 이 값인지"를 실험으로 정한다**는 것이 이 문서의 목적이다. 공공데이터 API에서 1,000번째 요청의 예외를 200ms 지연으로 해결했던 것과 같은 방식이다.

## 7. 기록 규칙

- `EXPLAIN` 결과는 **원문 그대로** 붙인다. 요약하지 않는다
- 측정은 **3회 이상**, p50·p95를 함께 적는다. 평균만 적지 않는다
- 예상과 다르면 **예상을 지우지 말고 둘 다 남긴다**
- 개선 전후를 비교할 때는 **한 번에 한 가지만** 바꾼다
