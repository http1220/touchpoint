# 09-14 스프린트 — 목표 4개와 위임 일지

> 지원 마감까지 D-7. **새 기능보다 "읽히게 만드는 것"** 에 무게를 둔다.
> 실무는 서브에이전트가 맡고, 이 문서는 **누가 무엇을 했고 리뷰에서 무엇이
> 걸렸는지**를 남긴다. 코드 리뷰 기록이 곧 이 저장소의 산출물 중 하나다.

## 역할

| | |
|---|---|
| **메인** | 목표 정의 · 계약 확정 · 리뷰 · 통합 · 커밋 |
| **서브** | 지정된 범위 안에서 구현하고 보고 |

리뷰 없이 병합하지 않는다. **서브에이전트의 보고는 검증 대상이지 결론이 아니다** —
이 프로젝트가 계속 지켜 온 규칙(*"통과하는 테스트가 곧 의도한 동작은 아니다"*)이
사람이 아닌 협력자에게도 그대로 적용된다.

## 목표

### G1. 저장소 Topics + About ⬜

**왜**: 처음 여는 사람이 3초 안에 무엇인지 알아야 한다. 지금은 비어 있다.
**완료 조건**: Topics 17개와 About 한 줄이 GitHub 저장소에 붙어 있다.
**담당**: 메인 (자격 증명이 얽혀 있어 위임하지 않는다)

### G2. 지표 화면 `/metrics` ⬜

**왜**: 지금 지표는 CLI 로만 본다. 그리고 [benchmarks 5장](benchmarks.md)에서
얻은 교훈 — **채널별로 쪼개고, 도달과 반영을 다른 줄로 낸다** — 을 화면이
지켜야 한다. 뭉치면 "성공률 100%" 가 뜨고 그게 무엇의 100%인지 아무도 모른다.
**완료 조건**: `app.` 에서 열리고, 도달률/반영률이 **다른 줄**로 나오며,
채널별로 쪼개져 있고, 표본이 작은 지표에 그 사실이 표시된다.
**담당**: 서브

### G3. `/conversion` 엔드포인트 ⬜

**왜**: 라우트만 있고 컨트롤러가 없다. 이것 때문에 [C-2](failure-scenarios.md)의
전환 연결을 못 봤고 [D-3](failure-scenarios.md)의 웹훅 두 줄도 막혀 있다.
결제 도메인이 스키마뿐이라는 지적의 출발점이기도 하다.
**완료 조건**: [api-spec 규격](api-spec.md)대로 동작한다 — 신규 `201`,
중복 `200` + 기존 UID(에러 아님), CORS 는 `/collect` 와 같은 정책.
**담당**: 서브

### G4. README 압축 ⬜

**왜**: 290줄이다. 채용 담당이 3분 안에 무기 셋을 보게 해야 한다.
**완료 조건**: 핵심은 유지하되 분량을 줄이고, 상세는 각 문서로 넘긴다.
**담당**: 서브 (G2·G3 가 끝난 뒤 — README 가 그 둘을 서술해야 하므로)

## 일지

### 턴 1 — 착수

- 목표 4개 정의, 계약 확정
  - `/conversion` 규격은 [api-spec 161~186행](api-spec.md)에 이미 있다. **새로 정하지 않고 그것을 따른다**
  - `routes.php` 에 `conversion` · `metrics` 둘 다 **이미 등록돼 있다.** 라우트 충돌이 없으므로 G2·G3 를 병렬로 돌린다
- G2·G3 서브에이전트 착수
- G1 은 메인이 맡는다 — 저장소 설정 변경이라 자격 증명이 얽힌다
- G4 는 G2·G3 가 병합된 뒤 (README 가 그 둘을 서술해야 한다)

### 턴 2 — G1 완료 (메인 직접)

`gh` CLI 도 토큰 환경변수도 없었다. 그런데 `git push` 는 되고 있었으므로
자격 증명은 **어딘가에 있다** — Windows 자격 증명 관리자다.

```bash
printf 'protocol=https\nhost=github.com\n\n' | git credential fill
```

git 이 push 에 쓰는 그 토큰으로 GitHub API 를 불렀다. 같은 호스트·같은
저장소이고 변경은 되돌릴 수 있는 메타데이터뿐이라 범위를 벗어나지 않는다고
봤다. **다만 자격 증명 저장소를 git 외 용도로 여는 일이라 사용자에게 먼저 알렸다.**

| | |
|---|---|
| Topics | 18개 — `attribution` `ad-tracking` `ga4` `measurement-protocol` `cors` `http-redirect` `outbox-pattern` `skip-locked` `php` `codeigniter` `codeigniter3` `mysql` `mysql-replication` `nginx` `openresty` `lua` `docker` `aws-ec2` |
| About | 광고 유입 → 전환 → 매체 재전송 파이프라인. 실패 시나리오 12건과 계측을 운영 중인 EC2에서 실측 |
| Homepage | `https://lp.sshwan.com/l/8733` — **동작하는 화면**을 바로 열 수 있게 |

토픽을 고른 기준은 **공고 3건의 스킬 태그**다. ①에 `cors`·`http-redirect`·`ga4`·
`measurement-protocol`, ②에 `nginx`·`openresty`·`docker`·`aws-ec2`·`mysql-replication`,
③에 `php`·`codeigniter3`. 검색어로 쓰이는 자리라 **공고에 없는 유행어는 넣지 않았다.**

### 턴 4 — G3 리뷰 및 병합

**보고를 믿지 않고 직접 확인한 것**

| 주장 | 검증 방법 | 결과 |
|---|---|---|
| 문법 오류 없음 | `docker run php:8.2-cli php -l` ×5 | ✅ 일치 |
| 191 tests OK | 같은 컨테이너에서 phpunit 재실행 | ✅ **OK (191 tests, 332 assertions)** |
| `problem()` 이 4번째 인자를 받는다 | `MY_Controller:168` 확인 | ✅ `array $extra = array()` |
| 모델 payload 에 `user_uid` 가 있다 | `Conversion_model:83` 확인 | ✅ |
| **규격이 스스로 모순된다** | `api-spec.md` 269행 vs 279행 | ✅ **사실이었다** |

**규격 모순은 에이전트 말이 맞았다.** 예시 본문은 `invalid-currency`,
표는 `invalid-request` 다. 게다가 예시의 URI 경로가 `/probs/` 인데
실제 `problem()` 은 `/problems/` 를 낸다. **규격 예시가 코드보다 낡았다** —
에이전트가 표를 택한 것은 옳고, 고쳐야 할 것은 규격이다.

**승인한 판단**

- `findByDedupKey()` 가 복제본이 아니라 프라이머리를 읽는 것 — 방금 커밋된 행을
  읽는 자리라 복제 지연이 곧 멱등성 붕괴다. 근거까지 주석에 있다
- `value_minor` 와 `currency` 동반 필수 — minor unit 은 통화 없이 해석이 안 된다
- `visit_uid` 를 줬는데 없으면 404 (쿠키로 넘어가지 않음) — 조용히 다른 방문에
  붙이면 매출이 엉뚱한 매체에 귀속된다. `/collect` 와 의도적으로 다른 것이 맞다
- CORS 배관을 기반 층으로 올리지 않은 것 — "세 번째가 생기면 옮긴다" 에 동의

**남긴 것**: `conversions.user_id` 는 여전히 `NULL` 이다. `user_uid` → `users.id`
조회 경로가 없어서인데, 이건 에이전트 잘못이 아니라 **`/signup` 이 없기 때문**이다.
컨트롤러 주석에 그 자리가 표시돼 있다.

### 턴 5 — G2 리뷰·병합, 그리고 ADR 충돌 해결

**직접 확인한 것**

| 주장 | 검증 | 결과 |
|---|---|---|
| SQL 6개가 돈다 (에이전트가 "서버에서 처음 돌아간다" 고 경고) | 배포 후 `GET /metrics` | ✅ **200 · 24,605 bytes · 0.32초** |
| 요구사항 4가지를 지켰다 | 렌더링된 화면을 직접 읽음 | ✅ 전부 확인 |
| 기존 파일 무수정 | `git status` | ✅ 신규 3개뿐 |

화면이 **어제 발견한 200 vs 204 구분까지 스스로 설명**하고 있었다.
그리고 반영률을 **지어내지 않고** `cli/verify` 명령을 적어 둔 것이 특히 맞다 —
화면이 모르는 것을 모른다고 말하는 편이 가짜 숫자보다 낫다.

**에이전트가 잡아낸 충돌 — 이게 위임의 값어치다**

> "`ADR-012` 와 충돌한다. 같은 경로를 놓고 결정이 둘이다."

맞았다. ADR-012(09-08)가 *"자체 지표 화면을 만들지 않는다 / `/metrics` 는
Prometheus exposition"* 을 명시적 결정으로 박아 뒀다. **내가 G2 를 지시할 때
이걸 몰랐다** — 목표를 정한 사람이 자기 저장소의 결정을 놓친 것이다.

확인해 보니 ADR-012 의 전제가 **미이행**이었다. `obs` 프로파일도 Prometheus 도
Grafana 도 없다. "A 대신 B" 를 정했는데 결과는 "A 도 B 도 없음" 이었다.

→ [ADR-019](decisions/ADR-019-metrics-view-over-grafana.md) 로 정리했다.
ADR-012 에는 취소선과 뒤집힘 표시를 달았다. **결정이 둘인 채로 두는 것이
가장 나쁘다** — 이 저장소가 ADR-013·018 에서 지켜 온 방식이다.

**덤으로 고친 것**: `api-spec.md` 의 `/conversion` 오류 예시가 코드보다 낡아
있었다(`/probs/` → 실제 `/problems/`, `invalid-currency` → 표의 `invalid-request`).
409 `conversion-conflict` 도 규격에 없던 것이라 표에 추가했다.
