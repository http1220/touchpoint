# 09-14 스프린트 — 목표 4개와 위임 일지

> 지원 마감까지 D-7. **새 기능보다 "읽히게 만드는 것"** 에 무게를 둔다.
> 실무는 서브에이전트가 맡고, 이 문서는 **누가 무엇을 했고 리뷰에서 무엇이
> 걸렸는지**를 남긴다. 코드 리뷰 기록이 곧 이 저장소의 산출물 중 하나다.

## 역할

| | |
|---|---|
| **메인** | 목표 정의 · 계약 확정 · 리뷰 · 통합 · 커밋 |
| **서브** | 지정된 범위 안에서 구현하고 보고 |

리뷰 없이 병합하지 않는다. **서브에이전트의 보고는 검증 대상이지 결론이 아니다** —
이 프로젝트가 계속 지켜 온 규칙(*"통과하는 테스트가 곧 의도한 동작은 아니다"*)이
사람이 아닌 협력자에게도 그대로 적용된다.

## 목표

### G1. 저장소 Topics + About ✅

**왜**: 처음 여는 사람이 3초 안에 무엇인지 알아야 한다. 지금은 비어 있다.
**완료 조건**: Topics 17개와 About 한 줄이 GitHub 저장소에 붙어 있다.
**담당**: 메인 (자격 증명이 얽혀 있어 위임하지 않는다)

### G2. 지표 화면 `/metrics` ✅

**왜**: 지금 지표는 CLI 로만 본다. 그리고 [benchmarks 5장](benchmarks.md)에서
얻은 교훈 — **채널별로 쪼개고, 도달과 반영을 다른 줄로 낸다** — 을 화면이
지켜야 한다. 뭉치면 "성공률 100%" 가 뜨고 그게 무엇의 100%인지 아무도 모른다.
**완료 조건**: `app.` 에서 열리고, 도달률/반영률이 **다른 줄**로 나오며,
채널별로 쪼개져 있고, 표본이 작은 지표에 그 사실이 표시된다.
**담당**: 서브

### G3. `/conversion` 엔드포인트 ✅

**왜**: 라우트만 있고 컨트롤러가 없다. 이것 때문에 [C-2](failure-scenarios.md)의
전환 연결을 못 봤고 [D-3](failure-scenarios.md)의 웹훅 두 줄도 막혀 있다.
결제 도메인이 스키마뿐이라는 지적의 출발점이기도 하다.
**완료 조건**: [api-spec 규격](api-spec.md)대로 동작한다 — 신규 `201`,
중복 `200` + 기존 UID(에러 아님), CORS 는 `/collect` 와 같은 정책.
**담당**: 서브

### G4. README 압축 ✅

**왜**: 290줄이다. 채용 담당이 3분 안에 무기 셋을 보게 해야 한다.
**완료 조건**: 핵심은 유지하되 분량을 줄이고, 상세는 각 문서로 넘긴다.
**담당**: 서브 (G2·G3 가 끝난 뒤 — README 가 그 둘을 서술해야 하므로)

## 일지

### 턴 1 — 착수

- 목표 4개 정의, 계약 확정
  - `/conversion` 규격은 [api-spec 161~186행](api-spec.md)에 이미 있다. **새로 정하지 않고 그것을 따른다**
  - `routes.php` 에 `conversion` · `metrics` 둘 다 **이미 등록돼 있다.** 라우트 충돌이 없으므로 G2·G3 를 병렬로 돌린다
- G2·G3 서브에이전트 착수
- G1 은 메인이 맡는다 — 저장소 설정 변경이라 자격 증명이 얽힌다
- G4 는 G2·G3 가 병합된 뒤 (README 가 그 둘을 서술해야 한다)

### 턴 2 — G1 완료 (메인 직접)

`gh` CLI 도 토큰 환경변수도 없었다. 그런데 `git push` 는 되고 있었으므로
자격 증명은 **어딘가에 있다** — Windows 자격 증명 관리자다.

```bash
printf 'protocol=https\nhost=github.com\n\n' | git credential fill
```

git 이 push 에 쓰는 그 토큰으로 GitHub API 를 불렀다. 같은 호스트·같은
저장소이고 변경은 되돌릴 수 있는 메타데이터뿐이라 범위를 벗어나지 않는다고
봤다. **다만 자격 증명 저장소를 git 외 용도로 여는 일이라 사용자에게 먼저 알렸다.**

| | |
|---|---|
| Topics | 18개 — `attribution` `ad-tracking` `ga4` `measurement-protocol` `cors` `http-redirect` `outbox-pattern` `skip-locked` `php` `codeigniter` `codeigniter3` `mysql` `mysql-replication` `nginx` `openresty` `lua` `docker` `aws-ec2` |
| About | 광고 유입 → 전환 → 매체 재전송 파이프라인. 실패 시나리오 12건과 계측을 운영 중인 EC2에서 실측 |
| Homepage | `https://lp.sshwan.com/l/8733` — **동작하는 화면**을 바로 열 수 있게 |

토픽을 고른 기준은 **공고 3건의 스킬 태그**다. ①에 `cors`·`http-redirect`·`ga4`·
`measurement-protocol`, ②에 `nginx`·`openresty`·`docker`·`aws-ec2`·`mysql-replication`,
③에 `php`·`codeigniter3`. 검색어로 쓰이는 자리라 **공고에 없는 유행어는 넣지 않았다.**

### 턴 4 — G3 리뷰 및 병합

**보고를 믿지 않고 직접 확인한 것**

| 주장 | 검증 방법 | 결과 |
|---|---|---|
| 문법 오류 없음 | `docker run php:8.2-cli php -l` ×5 | ✅ 일치 |
| 191 tests OK | 같은 컨테이너에서 phpunit 재실행 | ✅ **OK (191 tests, 332 assertions)** |
| `problem()` 이 4번째 인자를 받는다 | `MY_Controller:168` 확인 | ✅ `array $extra = array()` |
| 모델 payload 에 `user_uid` 가 있다 | `Conversion_model:83` 확인 | ✅ |
| **규격이 스스로 모순된다** | `api-spec.md` 269행 vs 279행 | ✅ **사실이었다** |

**규격 모순은 에이전트 말이 맞았다.** 예시 본문은 `invalid-currency`,
표는 `invalid-request` 다. 게다가 예시의 URI 경로가 `/probs/` 인데
실제 `problem()` 은 `/problems/` 를 낸다. **규격 예시가 코드보다 낡았다** —
에이전트가 표를 택한 것은 옳고, 고쳐야 할 것은 규격이다.

**승인한 판단**

- `findByDedupKey()` 가 복제본이 아니라 프라이머리를 읽는 것 — 방금 커밋된 행을
  읽는 자리라 복제 지연이 곧 멱등성 붕괴다. 근거까지 주석에 있다
- `value_minor` 와 `currency` 동반 필수 — minor unit 은 통화 없이 해석이 안 된다
- `visit_uid` 를 줬는데 없으면 404 (쿠키로 넘어가지 않음) — 조용히 다른 방문에
  붙이면 매출이 엉뚱한 매체에 귀속된다. `/collect` 와 의도적으로 다른 것이 맞다
- CORS 배관을 기반 층으로 올리지 않은 것 — "세 번째가 생기면 옮긴다" 에 동의

**남긴 것**: `conversions.user_id` 는 여전히 `NULL` 이다. `user_uid` → `users.id`
조회 경로가 없어서인데, 이건 에이전트 잘못이 아니라 **`/signup` 이 없기 때문**이다.
컨트롤러 주석에 그 자리가 표시돼 있다.

### 턴 5 — G2 리뷰·병합, 그리고 ADR 충돌 해결

**직접 확인한 것**

| 주장 | 검증 | 결과 |
|---|---|---|
| SQL 6개가 돈다 (에이전트가 "서버에서 처음 돌아간다" 고 경고) | 배포 후 `GET /metrics` | ✅ **200 · 24,605 bytes · 0.32초** |
| 요구사항 4가지를 지켰다 | 렌더링된 화면을 직접 읽음 | ✅ 전부 확인 |
| 기존 파일 무수정 | `git status` | ✅ 신규 3개뿐 |

화면이 **어제 발견한 200 vs 204 구분까지 스스로 설명**하고 있었다.
그리고 반영률을 **지어내지 않고** `cli/verify` 명령을 적어 둔 것이 특히 맞다 —
화면이 모르는 것을 모른다고 말하는 편이 가짜 숫자보다 낫다.

**에이전트가 잡아낸 충돌 — 이게 위임의 값어치다**

> "`ADR-012` 와 충돌한다. 같은 경로를 놓고 결정이 둘이다."

맞았다. ADR-012(09-08)가 *"자체 지표 화면을 만들지 않는다 / `/metrics` 는
Prometheus exposition"* 을 명시적 결정으로 박아 뒀다. **내가 G2 를 지시할 때
이걸 몰랐다** — 목표를 정한 사람이 자기 저장소의 결정을 놓친 것이다.

확인해 보니 ADR-012 의 전제가 **미이행**이었다. `obs` 프로파일도 Prometheus 도
Grafana 도 없다. "A 대신 B" 를 정했는데 결과는 "A 도 B 도 없음" 이었다.

→ [ADR-019](decisions/ADR-019-metrics-view-over-grafana.md) 로 정리했다.
ADR-012 에는 취소선과 뒤집힘 표시를 달았다. **결정이 둘인 채로 두는 것이
가장 나쁘다** — 이 저장소가 ADR-013·018 에서 지켜 온 방식이다.

**덤으로 고친 것**: `api-spec.md` 의 `/conversion` 오류 예시가 코드보다 낡아
있었다(`/probs/` → 실제 `/problems/`, `invalid-currency` → 표의 `invalid-request`).
409 `conversion-conflict` 도 규격에 없던 것이라 표에 추가했다.

### 턴 6 — 통합 검증

병합한 둘을 **따로가 아니라 같이** 확인했다. 각각 잘 도는 것과
서로를 안 깨뜨리는 것은 다른 문제다.

| 경로 | 코드 | 시간 |
|---|---|---|
| `lp./go?work=8733` | 302 | 0.048s |
| `lp./l/8733` | 200 | 0.056s |
| `app./metrics` | 200 | **0.320s** |
| `app./readyz` | 200 | 0.040s |
| `api./track.js` | 200 | 0.064s |

**호스트 제한이 살아 있다** — `lp./metrics` 404, `api./conversion` GET 405.
`/metrics` 가 0.32초로 가장 느리다. 전부 풀스캔 집계라 `dispatch_log` 가
커지면 여기가 먼저 비싸진다(에이전트가 보고한 그대로다).
지금은 1만 행 규모라 감수한다.

CI 3건 전부 green.

G4 착수 — G2·G3 가 병합된 뒤라야 README 가 그 둘을 서술할 수 있다.

### 턴 7 — G4 리뷰·병합, 그리고 README 가 거짓말을 하고 있었다

**298줄 → 156줄.** 무기 셋(예상이 틀린 곳 / 계측 / 실패 시나리오)이 1~3장으로
올라왔고 "예상이 틀린 곳 넷" 표가 본문 맨 처음에 온다.

**에이전트가 확신 못 한 7가지를 전부 확인했다**

| 에이전트의 우려 | 확인 결과 |
|---|---|
| `Secure` 쿠키·HTTP/2 경고를 링크 없이 지웠다 | **유실 아님** — `architecture.md:183` 에 살아 있다 |
| 500 → 543 으로 고친 것이 맞나 | **맞다.** 대조 분모는 `204` 를 받은 543건이다 |
| 4.8% 와 5% 가 한 문서에 같이 있다 | **고쳤다.** 측정값인 4.8% 로 통일 |
| "계측 7장 중 5장" 이 지금도 맞나 | **틀렸다.** `benchmarks.md` 는 0~7장 구성이라 8개다. `1·2·3·5·6장 실측` 으로 바꿨다 |
| mermaid 빈 줄 제거가 렌더링을 깨지 않나 | **정상.** mermaid 10.9.1 로 렌더 확인 |
| ADR 18 → 19 | **맞다.** `docs/decisions/` 에 19개 |
| 한계 2건을 새로 추가했다 | **승인.** 없는 것을 없다고 적는 쪽이 맞다 |

**그런데 리뷰하다 더 큰 것이 나왔다 — README 가 없는 기능을 있다고 적고 있었다.**

압축 이전부터 있던 문장이다.

> ~~"PG 는 **테스트 모듈 2개**에 결제 완료 알림까지 붙습니다. GA4·**Meta** 는 실제 전송"~~

확인해 보니 **셋 다 없다.**

```
PG 모듈      application/ src/ 어디에도 없음. payments 는 마이그레이션뿐
Meta 채널    src/Channel/ 에 Ga4Channel · NoopChannel 둘뿐
결제 알림    코드 없음
```

포트폴리오에서 이건 가장 나쁜 종류의 오류다. **면접에서 "Meta 어댑터 보여
주세요" 한마디에 무너진다.** "아직 없는 것" 문단으로 바꿔 적고, 다이어그램의
Meta 노드도 점선 + `미구현` 으로 표시했다.

**`architecture.md` 에는 더 있었다**

| 어디 | 무엇 | 고친 것 |
|---|---|---|
| 36행 | **철회된 ADR-002 를 "이 프로젝트의 전부" 라고 인용** | ADR-018 로 고치고, 과대평가했던 과정을 각주로 |
| 152행 | **"복제본을 실제로 띄우지는 않되"** | **거짓이다.** 띄우고 있고 E-1 을 실측했다 |
| 179행 | "신규 매체 = 클래스 1개 + 설정 1줄" 을 사실처럼 | **주장**이라고 명시. 구현체가 하나뿐이라 미검증 |
| 202행 | "PG 테스트 모듈 2개를 붙인다" | 설계만 있고 구현 안 함 |
| 21행 | 수집을 `third-party` 로 표기 | 도메인이 하나라 third-party 가 아니다 |

**배운 것**: G4 는 "압축" 과제였는데 **진짜 산출물은 거짓말 제거**였다.
줄이려고 문장을 하나씩 들여다본 것이 계기다 — 압축이 감사(監査)를 강제했다.
그리고 철회된 결정을 근거로 인용하는 실수가 **이 저장소에서 네 번째**다.

## 마무리 — 위임에서 배운 것

목표 4개 전부 완료. 서브에이전트 3개가 코드를 쓰고 메인이 리뷰·통합했다.

### 서브가 메인보다 나았던 곳

**G2 가 `ADR-012` 충돌을 잡았다.** 목표를 지시한 내가 저장소의 기존 결정을
놓쳤고, 시킨 쪽이 아니라 **시킴을 당한 쪽이** 그걸 찾아냈다.
찬 상태에서 시작한 에이전트가 문서를 처음부터 읽은 덕이다 —
맥락이 있다는 것은 **이미 아는 것을 다시 확인하지 않는다**는 뜻이기도 하다.

**G3·G4 가 자기 확신 없는 것을 명시했다.** G4 는 7가지를 "확인 못 했다" 고
적어 냈고 그중 두 개가 실제 문제였다. **모른다고 말하는 보고가 검증을 싸게 만든다.**

### 메인이 해야 했던 곳

리뷰 없이 병합했다면 들어갔을 것들:

| | |

### 턴 8 — ADR-019 의 사실관계를 고쳤다

사용자가 물었다: *"Grafana 로 대체한다는 미이행 전제를 지금 구현하기 전에,
이와 충돌되는 전제와 결정이 있나?"*

**있었다. 그리고 내가 어제 놓친 것이었다.**

[ADR-014](decisions/ADR-014-stack-alignment.md)(스택 정렬, 09-08) 결과 절:

> 일정 순증 약 2.7일. Meta CAPI · 인덱스 EXPLAIN 실측 · **Prometheus·Grafana를
> 잘라 상쇄한다**
> **Prometheus·Grafana 대신 Lua 복제본 배정이 인프라 포지션 대응을 맡는다**
> (ADR-012 **수정**)

| | 결정 | 내용 |
|---|---|---|
| ADR-012 | 09-08 | 자체 화면 버림. **Grafana 가 대신함** |
| **ADR-014** | **09-08** | **그 Grafana 를 잘라 일정을 상쇄** |
| ADR-019 | 09-14 | 빈자리를 자체 화면으로 채움 |

**어제 내가 ADR-019 에 "전제가 이행되지 않았다" 고 적은 것은 틀렸다.**
안 만들어진 게 아니라 **ADR-014 가 명시적으로 잘랐다.** 누락과 결정은 다르고,
근거로서는 후자가 훨씬 강한데 **약한 쪽으로 적어 놓고 있었다.**

원인은 ADR-012 **본문만 읽고 그것을 참조하는 다른 ADR 을 역추적하지 않은 것**이다.
G2 에이전트가 잡아 준 충돌을 조사하면서도 같은 종류의 누락을 반복했다 —
**결정 사이의 연결을 놓친 다섯 번째**다.

**고친 것**

- `ADR-019` — ①번 근거를 "미이행" → "ADR-014 가 같은 날 잘랐다" 로. `되돌리는 조건` 절 신설
- `ADR-012` — 뒤집힘 주석에 ADR-014 를 명시
- `ADR-014` — 컷 항목에 "이 컷이 ADR-012 의 전제를 없앴다.
  **Grafana 를 되살리려면 이 항목부터 뒤집어야 한다**" 를 추가

**세 ADR 이 이제 서로를 가리킨다.** 한 곳만 읽어도 나머지로 갈 수 있다 —
이번 실수의 재발을 막는 것은 문장이 아니라 이 링크다.

### 턴 11 — 구현 에이전트가 한도로 끊겼다. 이어받았다

`Payment_model::applyEvent()` 를 쓰려던 참에 API 한도로 종료됐다.
**남은 것을 새 에이전트에 다시 시키지 않고 메인이 이어받았다** — 다시
시키면 이미 한 일을 재확인하느라 같은 비용을 또 치른다.

**받은 것 먼저 검증**

| | 결과 |
|---|---|
| `php -l` 14개 파일 | 전부 통과 |
| `phpunit` | **OK (317 tests, 600 assertions)** — 기존 191 + 신규 126 |
| `Payment_model` 완결성 | 617줄, 닫는 괄호까지 온전 |

**핵심 세 가지를 눈으로 확인했다**

- **CAS** — `UPDATE … WHERE id=? AND status IN (…)` 한 문장. `SELECT` 선행 없음 ✅
- **대조군** — `transitionByPrecheck()` 가 일부러 틀리게 구현돼 있고,
  주석이 *"`affected_rows` 를 보지 않는다. 이미 captured 인 행에 captured 를
  쓰면 MySQL 이 0을 돌려주는데 그걸 '막혔다' 로 읽으면 **대조군이 우연히
  정상처럼 보인다.** 틀린 코드는 틀린 그대로 재현돼야 한다"* 라고 적혀 있다.
  **내가 지시하지 않은 함정을 스스로 찾아 막았다**
- **중첩 트랜잭션 경고** — `Payment_model` 과 `Conversion_model` 양쪽에 있다 ✅

**메인이 마저 만든 것**

| 파일 | |
|---|---|
| `controllers/Webhook.php` | 서명 → 본문 → 조회 → `applyEvent` → 200. **무시도 200** |
| `controllers/cli/Pg.php` | 스텁 PG. `sign` 이 셸 변수를 뱉어 `xargs -P8` 이 동시성을 만든다 |
| `config/routes.php` | 웹훅 라우트 |

### 턴 12 — D-3 의 못 잰 두 줄을 마저 쟀다

| 시나리오 | 결과 |
|---|---|
| 웹훅 중복 수신 (동시 8개) | **전이 1 · 무시 15 · 코인 1 · 전환 1** ✅ |
| 웹훅 순서 역전 | **`captured_at` 불변** ✅ |
| 대조군 (SELECT 후 판정) | **전이 2 · 코인 2** ← 사고 재현 ✅ |

**범위 안 12건이 11건 완료 + 1건 부분이 됐다.**

#### 배포하며 잡은 것 둘

**① CSRF 제외 패턴이 요청 URI 와 안 맞았다.** `/purchase` 가 403 이었다.
`webhook/.*` 는 `webhooks/pg` 에 맞지 않는다 — `csrf_exclude_uris` 는
라우팅 **뒤**의 컨트롤러 이름이 아니라 요청 URI 와 대조된다.
`purchase` 는 목록에 아예 없었다. 넣는 근거도 주석에 적었다 —
**CSRF 가 막는 것은 "올라탄 인증 요청" 인데 올라탈 세션이 없다.**

**② `cli/pg sign` 의 경로 인자가 쪼개졌다.** 동시 8개에서 **401 여덟 개**를
받고 알았다. 서명은 맞는데 본문이 0바이트였다. CI3 의 CLI 인자는
**URI 세그먼트**라 `/tmp/pg-body.json` 이 `tmp` 로 잘렸다. 상수로 고정했다.

#### 대조군이 처음에 재현되지 않았다 — 이게 오늘 제일 값진 것

`PAYMENT_WEBHOOK_PRECHECK=true` 로 틀린 경로를 켰는데 **정상과 똑같이
`applied 1 · ignored 7`** 이 나왔다.

계획서가 *"엣지 로그의 8건 수신 시각 폭을 확인하라 — 벌어져 있으면 동시가
아니었다"* 고 적어 뒀는데 **내가 그걸 건너뛰고 결론부터 보려 했다.**
확인해 보니 8건이 같은 초에 도착했으므로 동시성은 있었다. 원인은 다른 데
있었다 — 요청이 20~40ms 로 짧아 두 번째가 `SELECT` 할 때 첫 번째가 이미
커밋돼 있었고, 그래서 `captured` 를 읽고 **스스로 물러났다.**

> **그게 check-then-act 버그의 진짜 성질이다.** 늘 터지지 않는다.
> 부하가 높거나 쿼리가 느려질 때만 창이 열린다 — **그래서 운영에 살아남고,
> 재현하려 들면 "안 되는데요" 가 된다.**

창을 400ms 벌리자 **8건 중 2건이 통과**했다. 12.5%가 아니라 25%다.
그리고 그 비율은 부하에 따라 움직인다 — **고정된 숫자가 아니다.**

피해의 모양이 특히 읽을 값이 있다.

| | 정상(CAS) | 대조군 |
|---|---|---|
| `payments.status` | `captured` | `captured` |
| `conversions` | 1 | **1** (`uq_dedup` 이 막았다) |
| **`coin_lots`** | 1 | **2** |

**결제 장부만 보면 정상이다.** 금액도 한 번이고 전환도 한 건이다.
틀어진 것은 코인뿐이고, 증상은 "결제 오류" 가 아니라 **"재화 초과 지급"** 으로
나타난다. `coin_lots` 에 UNIQUE 가 없어 **CAS 가 유일한 방어선**이었고,
그 하나를 빼자 바로 뚫렸다.

### 턴 13 — 남은 작업과 루트 도메인 홈

**① 파기 배치 cron** — 매일 04:43, 감사 로그(`~/logs/purge.log`).
문서에는 *"무인 삭제 전에 plan 을 며칠 지켜보겠다"* 고 적어 뒀는데 **바꿨다.**
D-7 이라 며칠을 지켜볼 시간이 없고, **파기되지 않는 보존정책은 정책이 아니다.**
대신 로그를 남겨 무엇이 언제 지워졌는지 추적할 수 있게 했다.

**② 결제의 유입 귀속** — `payments.visit_id` 를 더했다.

전에는 결제 전환이 **무조건 `users.signup_visit_id`(가입 접점)** 로 갔다.
가입은 A 광고로 하고 석 달 뒤 B 광고를 보고 돌아와 결제할 수 있는데,
그 매출을 무조건 A 에 붙이고 있었다. **first-touch 를 고른 게 아니라
고를 수 없었던 것이다 — 설계가 아니라 누락이었다.**

실측: 광고(`pid=paytest`)를 타고 들어와 결제했더니

```
payments.visit_id  870        ← 결제 시점 방문
conversions.visit_id 870
touchpoints        pid=paytest (first·last)
conversions.user_id  3        ← 이 경로에서 처음 채워졌다
```

FK 도 인덱스도 걸지 않았다. FK 는 E-2 에서 확인한 이유(visits 3개월 ·
payments 5년), 인덱스는 1-3 에서 확인한 이유(쓰는 쿼리를 보고 만든다).

**③ 루트 도메인에 웹툰 홈**

사용자가 *"투믹스 메인을 그대로 베껴도 좋다"* 고 했지만 **베끼지 않았다.**
지원하는 회사에 그 회사 페이지 복제본을 내는 모양이 되고, 이 저장소의
익명화 원칙과도 어긋난다. 대신 **조사로 역추론한 도메인 개념**을
내 디자인으로 구현했다.

| 화면에 보이는 것 | 스키마의 무엇 |
|---|---|
| 작품이 월·목 둘 다에 나온다 | `work_publish_days` 가 별도 테이블 |
| "72시간 후 무료" 뱃지 | `works.wait_free_hours` (**작품** 속성) |
| 회차별 무료/유료 | `episodes.is_charged` (**회차** 속성) |
| 전체·12+·15+ | `age_rating_code` (boolean 이 아닌 이유: 국가별 등급) |
| ko·en·ja 전환 | `locales` 의 lang/script/region 분리 |
| **랭킹이 회차 수 기준** | 조회수를 안 쓴 이유를 화면에도 적었다 — 조사한 두 플랫폼 모두 비공개였고 **없는 지표를 지어내면 그 순간 흉내가 된다** |

**nginx 를 갈라야 했다.** 전에는 한 블록이 `default_server` 이면서 루트
도메인이었는데, 거기 홈을 붙이면 **C-3 방어선이 사라진다**(모르는 Host 가
PHP 까지 닿아 오픈 리다이렉트가 된다). 이름 없는 기본 블록(302 고정)과
이름으로 매칭되는 루트 블록으로 나눴다. 배포 후 확인:

```
sshwan.com/                200 (홈)
Host: evil.example         302 → lp.sshwan.com    ← 방어선 유지
lp./  ·  app./             404                    ← 홈은 루트에만
```
