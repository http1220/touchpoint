# ADR-016 · 결제는 PG 테스트 연동, 알림은 채널 어댑터

**상태**: 확정 (2026-09-08) · **Phase 2** — [ADR-008](ADR-008-stub-pg.md)의 "스텁" 결정을 개정

## 배경

[ADR-008](ADR-008-stub-pg.md)은 **"PG는 스텁으로 만들고 상태 머신만 진짜로"** 를 택했다. 근거는 "PG를 하나 붙이는 건 이 문제(30곳 갈아끼우기)의 축소판도 아니다"였다.

**그 논리에 구멍이 있었다.** 어댑터 패턴을 증명하려면 **구현체가 둘 이상**이어야 한다. 스텁 하나로는 인터페이스가 옳은지 알 수 없다. 두 번째를 붙일 때 인터페이스가 깨지는 것이 어댑터 설계의 본질인데, 그걸 겪지 않고 넘어가고 있었다.

## 결정

### 결제 — PG 테스트 연동 **2곳 이상**

| 구현체 | 역할 |
|---|---|
| `StubGateway` | 시나리오 주입용 (중복 웹훅·순서 역전·타임아웃) |
| `PgAGateway` | **실제 PG 테스트 환경** |
| `PgBGateway` | **두 번째 PG** — 여기서 인터페이스가 검증된다 |

**두 번째를 붙일 때 무엇이 깨지는지를 기록하는 것**이 이 항목의 목적이다. 상태값 이름, 웹훅 페이로드, 에러 코드, 금액 단위, 멱등키 취급이 PG마다 다르다.

> **주의**: 사업자등록 없이 테스트 가능한 범위는 PG마다 다르다. 테스트 키를 공개하는 곳도 있고 계약이 필요한 곳도 있다. **착수 전에 각 사 문서로 확인하고 결과를 [worklog](../worklog.md)에 남긴다.** 두 곳을 못 붙이면 하나 + 스텁으로 후퇴한다.

### 알림 — 같은 어댑터 패턴을 두 번째로 증명

결제 완료 알림을 **채널 어댑터**로 만든다. 매체 전송([ADR-005](ADR-005-channel-adapter.md))과 **같은 구조**다.

| 채널 | 수단 | 개인 가능 여부 |
|---|---|---|
| **웹 푸시** | Service Worker + VAPID **직접 구현** | ✅ 비용 0, 외부 의존 0 |
| **SMS** | 국내 SMS 사업자 API | ✅ 단, **본인 명의 발신번호 사전등록** 필요 |
| ~~카카오 알림톡~~ | — | ❌ **사업자등록증 + 비즈니스 채널 인증 필수** |

> **알림이 어댑터라는 게 이 결정의 값어치다.** 매체 전송에서 한 번, 알림에서 또 한 번 — **같은 패턴이 다른 도메인에서도 성립한다**는 것을 보이면 그건 우연이 아니라 설계다.

## AWS 메시징 — 확인 결과

"AWS로 푸시가 되는가"를 확인했다.

| 서비스 | 상태 | 이 프로젝트에서 |
|---|---|---|
| **Amazon SNS** | 정상 | 모바일 푸시(APNs/FCM) + SMS. **앱이 있어야 모바일 푸시가 된다** |
| **Amazon Pinpoint** | **2026-10-30 지원 종료** | 캠페인·여정·세그먼트가 종료 대상. 신규 가입은 2025-05-20부터 차단 |
| **AWS End User Messaging** | 현행 | Pinpoint의 **트랜잭션 SMS·푸시·음성**이 이관돼 계속 제공 |
| **웹 푸시** | **AWS가 직접 제공하지 않음** | 직접 구현 |

**이 프로젝트는 웹이라 앱이 없다.** 따라서 AWS 모바일 푸시는 대상이 아니고, **웹 푸시를 직접 구현**하는 쪽이 맞다. 그리고 웹 개발자 포지션에는 이쪽이 더 어울린다 — 앱 푸시는 앱 개발자 영역이다.

> 다만 **"Pinpoint가 종료되고 End User Messaging으로 갔다"는 사실 자체가 면접 소재**다. AWS 메시징을 실제로 알아본 사람만 아는 내용이다.

## 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| 스텁 PG 하나만 (초판) | 구현체가 하나면 **어댑터가 옳은지 검증되지 않는다** |
| 결제 게이트웨이 서비스(여러 PG를 하나의 API로) | **추상화가 이미 돼 있어 어댑터를 직접 만들 이유가 사라진다.** 이 프로젝트가 증명하려는 것과 정반대 |
| 카카오 알림톡 | 사업자등록증 필수. 개인 불가 |
| AWS SNS로 모바일 푸시 | **앱이 없다** |
| Amazon Pinpoint | **2026-10-30 종료.** 지금 새로 붙일 이유가 없다 |
| 알림 없이 결제만 | "결제 완료를 사용자에게 어떻게 알리는가"는 실제 서비스의 필수 요소다 |
| Phase 1에 포함 | 13일에 불가능 |

## 결과

- **Phase 2**. 서류 지원 이후 착수
- **리드타임 주의**: SMS 발신번호 사전등록은 심사에 며칠 걸린다. **Phase 1 시작 시점에 미리 신청**한다
- **한계 명시**: PG는 테스트 환경이라 실제 정산·환불이 일어나지 않는다. **테스트 연동임을 README에 밝힌다**
- **얻는 것**: 어댑터 패턴이 **매체·결제·알림 세 도메인에서** 성립한다는 것을 보인다. 하나에서만 보이면 우연이고, 셋이면 설계다
