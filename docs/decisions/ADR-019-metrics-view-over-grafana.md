# ADR-019 · 지표 화면을 직접 만든다 — ADR-012 의 한 항목을 뒤집는다

**상태**: 확정 (2026-09-14) — [ADR-012](ADR-012-observability-scope.md) 의
*"자체 지표 화면을 만들지 않는다"* 를 **뒤집는다.** 나머지 항목(구조화 로그·
`trace_id`·`/health`·탐지 경로 기록)은 그대로 유효하다.

## 배경

ADR-012(09-08)는 이렇게 정했다.

> `/metrics` 를 **Prometheus exposition 형식**으로 노출한다.
> **자체 지표 화면(`/metrics` Chart.js 대시보드)을 만들지 않는다.**
> Grafana 가 그 역할을 대신한다.

09-14 에 지표 화면을 만들면서 이 결정과 정면으로 부딪혔다. 같은 경로를 놓고
결정이 둘이 된 상태라 하나를 골라야 한다.

## 결정

**`/metrics` 는 사람이 읽는 HTML 지표 화면이다.** Prometheus exposition 은
만들지 않는다. 나중에 붙인다면 **다른 경로**에 둔다.

## 근거

### ① 전제가 이행되지 않았다

ADR-012 가 대시보드를 버린 이유는 *"Grafana 가 그 역할을 대신한다"* 였다.
**대신하지 않았다** — `docker-compose.yml` 에 `obs` 프로파일도, Prometheus 도,
Grafana 도 없다. 6일이 지나도록 만들어지지 않았고 남은 기간에도 안 만든다.

버린 것의 대체재가 없으면 **버린 것이 그냥 없는 것**이다.
ADR-012 는 "A 대신 B" 를 정했는데 결과는 "A 도 B 도 없음" 이었다.

### ② 상자가 그 사이에 측정됐다

ADR-012 는 Prometheus·Grafana 상시 기동을 OOM 위험으로 기각하면서도
프로파일 분리면 된다고 봤다. 그 뒤 [리소스를 실측했다](../benchmarks.md).

| | 유휴 | 부하 |
|---|---|---|
| MySQL 2대 | 메모리의 **90%** | CPU 의 **84%** |
| load average | 0.09 | **2.29** / vCPU 2 |

**메모리가 아니라 CPU 가 먼저 벽에 닿는다.** 컨테이너 둘을 더 띄우는 선택은
09-08 에 생각한 것보다 비싸다. 반면 HTML 한 장은 **쿼리 6개 · 0.32초**다.

### ③ ADR-012 가 알 수 없었던 요구사항이 생겼다

이게 결정적이다. [benchmarks 5장](../benchmarks.md)에서 지표 하나가
**사실 둘**이라는 것을 알았다.

```
도달률  543 / 543 = 100%     매체가 2xx 를 돌려줬다
반영률  517 / 543 = 95.2%    매체 보고서에 실제로 있다
```

그리고 전송 로그 9303행 중 **9300행이 `NoopChannel`** 이었다. 합치면 100% 가 뜬다.

**이건 시각화 도구가 풀어 주는 문제가 아니다.** Grafana 는 먹인 것을 그린다 —
Noop 과 GA4 를 한 숫자에 합쳐 먹이면 그대로 100% 를 그리고, "도달" 과 "반영" 을
한 이름으로 부르면 그 이름으로 그린다. **문제는 렌더링이 아니라 의미론**이었다.

그래서 화면이 지켜야 할 것을 화면 자신이 적게 했다.

| 규칙 | 구현 |
|---|---|
| 채널별로 쪼갠다 | 도달률·지연·재시도에 **합계 행을 만들지 않는다.** `noop` 에는 `가짜 채널` 태그 |
| 도달률 ≠ 반영률 | 화면은 도달률만 낸다. 반영률은 **지어내지 않고** `cli/verify` 명령을 적는다 |
| 표본을 밝힌다 | 100건 미만이면 `표본 N`. 분모가 0이면 비율을 만들지 않는다 |
| 분모를 같이 낸다 | `517 / 543 (95.2%)` 형태로만 출력하는 헬퍼 하나로 통일 |

> **Prometheus 를 붙였어도 이 네 가지는 우리가 정의해야 했다.**
> 도구를 바꾸는 것으로는 안 풀리는 문제였고, 그걸 09-08 에는 몰랐다.

### ④ 기각된 것은 이것이 아니다

ADR-012 가 버린 것은 **"Chart.js 대시보드"** 다. 지금 만든 것은
**JS 가 한 줄도 없는 HTML 표**다([ADR-009](ADR-009-no-spa.md) 그대로).
차트 라이브러리를 얹는 비용을 걱정한 결정이라면, 그 비용은 애초에 없다.

## 잃는 것

- **시계열이 없다.** 지금 값만 보이고 "어제보다 나빠졌나" 를 못 본다.
  Prometheus 를 버린 대가이고, 이 프로젝트 기간에는 감수한다
- **경보가 없다.** 사람이 열어 봐야 안다
- **`/metrics` 라는 이름이 관례를 배신한다.** 그 경로는 대개 기계가 긁는 자리다.
  붙인다면 exposition 은 `/metrics/prom` 같은 다른 경로로 간다

## 남은 위험

**인증이 없다.** 공개 호스트에서 누구나 열 수 있다. 개인정보나 식별자는 내지
않지만(채널명·건수·상태 코드·소요 시간뿐), **운영 규모는 드러난다.**
이 프로젝트는 시연용이라 그대로 두되, 실제 서비스라면 `/metrics` 는
내부망이나 인증 뒤에 둔다.

## 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| ADR-012 대로 Prometheus + Grafana | 6일간 안 만들어졌고 남은 기간에도 못 만든다. 그리고 ③의 의미론 문제를 안 풀어 준다 |
| 둘 다 만든다 | D-7 이다. 그리고 t3.small 이 CPU 에서 이미 포화 직전이다 |
| 경로를 갈라 `/dashboard` 로 | ADR-012 를 살려 두는 대신 **없는 것(exposition)이 좋은 경로를 계속 차지한다.** 있는 것에 이름을 주는 편이 낫다 |
| ADR-012 를 조용히 무시 | 이 저장소는 뒤집은 결정을 [ADR-013](ADR-013-caddy-over-nginx.md)·[ADR-018](ADR-018-single-registered-domain.md)처럼 **기록해 왔다.** 결정이 둘인 채로 두는 것이 가장 나쁘다 |
