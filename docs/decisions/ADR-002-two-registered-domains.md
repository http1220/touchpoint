# ADR-002 · 등록 도메인 2개로 분리

**상태**: 확정 (2026-09-01) — **이 프로젝트에서 가장 중요한 결정**

## 배경

초기 설계안은 서브도메인 3개(`lp.` / `api.` / `app.example.com`)를 "일부러 다른 오리진으로 갈라놓는다"고 했다. 목적은 CORS와 `SameSite`, 서드파티 쿠키 차단을 모두 겪는 것이었다.

## 문제

**브라우저의 same-site 판정 기준은 오리진이 아니라 등록 도메인(eTLD+1)이다.** 셋 다 `example.com`이면 same-site다.

| 겪겠다고 한 것 | 서브도메인 3개로 실제 벌어지는 일 |
|---|---|
| CORS preflight | 발생 (cross-origin은 맞음) |
| `SameSite=None; Secure` 필요 | **불필요.** `Lax`로도 쿠키가 전송됨 |
| 서드파티 쿠키 차단 재현 | **불가능.** 전부 first-party |
| "SameSite 3종 차이" 면접 답변 | **겪은 게 없어 책 내용밖에 말할 게 없음** |

→ 광고 어트리뷰션의 **핵심 난제를 하나도 못 겪은 채 끝난다.**

## 결정

**등록 도메인 2개**를 산다. 현실의 광고 추적처럼 **광고주 도메인 ≠ 추적 도메인**으로 가른다.

```
toonlab.example    lp.  (랜딩·브리지)   app. (서비스·전환·지표)
abridge.example    api. (수집 API)
```

| 호출 | 관계 | 역할 |
|---|---|---|
| `lp.toonlab` → `api.abridge` | **cross-site** | 실험군 |
| `lp.toonlab` → `app.toonlab` | same-site, cross-origin | **대조군** |

## 근거

**대조군이 있어야 증명이 된다.** "cross-site면 막히고 same-site면 통과한다"를 나란히 보여줘야, 원인이 오리진이 아니라 사이트라는 것이 드러난다. 한쪽만 있으면 관찰이지 실험이 아니다.

## 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| 서브도메인 3개 | 위 문제 |
| 로컬 `.test` 도메인 2개 (`adv.test` / `track.test`) | 비용 0에 재현은 되지만 **공개 데모 URL이 없다.** 채용담당자가 클릭할 곳이 없음 |
| 도메인 1개 + 다른 오리진 포트 | 포트는 same-site 판정에 영향을 주지 않는다 |

## 결과

- **비용**: 도메인 1개 값 추가 (연 1~2만원). 이 프로젝트에서 가장 값싼 지출
- **운영**: Caddy 한 대가 두 도메인 인증서를 각각 ACME로 발급. DNS A 레코드는 같은 EIP로
- **위험**: ACME rate limit. 설정 시행착오는 **staging 엔드포인트로 먼저** 검증한다
