# ADR-009 · SPA/React를 쓰지 않는다

**상태**: 확정 (2026-09-07)

## 배경

지원자의 실무 강점은 React·프론트엔드다. 익숙한 걸 쓰면 결과물이 더 좋아 보일 수 있다.

## 결정

**서버 렌더(CodeIgniter 뷰) + 바닐라 JS 추적 스니펫**으로 간다. React·Vue·SPA를 쓰지 않는다.

## 근거

**1. 지원 포지션이 프론트가 아니다.** React를 넣으면 "PHP 백엔드 지원자"가 아니라 "React 하던 사람이 PHP를 흉내 낸 것"으로 읽힌다. 지우려는 결격(PHP 경험 없음)이 오히려 부각된다.

**2. 대상 서비스가 서버 렌더 모놀리스다.** 실측 결과 플랫폼 A 공개 웹은 SPA가 아니다.

| 근거 | 관측값 |
|---|---|
| 정적 자산 | `/assets/js/web_v4/lib.min.js`, `style.2019.final.css` |
| 렌더링 | 서버가 완성된 HTML 반환 |
| 세션 | `…ci_session` (서버 세션) |

대조적으로 플랫폼 B는 SPA + 공개 JSON API다 → [조사 요약](../research-method.md)

**3. 추적 스니펫은 프레임워크가 없어야 배포된다.** `track.js`는 광고주 페이지에 붙는 코드다. 프레임워크 의존이 있으면 어디에도 못 붙인다. **현실의 광고 태그가 전부 바닐라인 이유가 이것이다.**

## 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| React SPA + PHP API | 포지션 불일치. 대상 서비스 구조와도 어긋남 |
| Next.js | 위와 동일 + 컨테이너 추가 |
| 지표 화면만 React | 화면 하나에 빌드 툴체인 전체를 들이는 건 과함 |

## 결과

- **지표 화면**: CI4 뷰 + Chart.js CDN 한 줄. 빌드 단계 없음
- **`track.js`**: 의존성 0. `fetch`와 `navigator.sendBeacon` 두 경로를 직접 구현 → [api-spec](../api-spec.md#3-post-apicollect--크로스사이트-수집--핵심)
- **감수**: 결과물의 시각적 완성도가 낮다. **의도된 것이며 README에 밝힌다**
- **참고**: 대상 조직에 프론트엔드 빌드 파이프라인이 여럿 있지만, 공개 채용 정보의 "내부 관리자 개발" 언급으로 보아 **어드민용**으로 추정된다. 공개 서비스가 SPA가 아니라는 판단과 모순되지 않는다 → [조사 요약](../research-method.md)
